Settled: **QuadTree** — the existing sortable quadrant-path `NodeKey` becomes the paged key (`0x00 ++ aligned_be ++ depth`), so a subtree stays one contiguous range; the SPX-004 overflow bucket shares the page file under `0x01 ++ totalOrder(x) ++ totalOrder(y) ++ pk`. **R-tree** — the arena already addresses nodes by logical `NodeId` (eviction-safe), so the paged key is the node id and the value the encoded node; the free list stays a head id + `Free(next)` slots. **Full-text** — postings become `term ++ 0x00 ++ pk → positions` (term-prefix scans are key-range scans) and `doc_len` becomes `pk → u32`, with `total_len` a resident counter.
- [x] 1.2 Page the spatial index — **both families done**. **QuadTree**: inserts/removes are copy-on-write inside the commit merge, region/radius/point queries decompose into key-range scans with exact-filter semantics preserved (SPX-020/021/023), the SPX-031 rebuild lifecycle is unchanged, and the canonical shape is still asserted bit-identical to a fresh rebuild. **R-tree**: the flat arena moved to `PagedTree` keyed by node id (split/condense/query algorithms untouched, since the arena already addressed nodes by logical id); nodes encode as little-endian records and insert/remove thread the superseded-page sink. Paged storage has no structural equality, so `verify_index_integrity` compares spatial indexes by contents — widened to the **whole** box, not just its lower corner, so an extent-only divergence still fails STG-007 rule 2 as the resident `PartialEq` did.
- [x] 1.3 Page the full-text index — postings and document lengths moved into one `PagedTree` under two prefix-separated keyspaces (`0x00 ++ term ++ 0x00 ++ pk → positions`, `0x01 ++ pk → doc_len`), so both fault and evict under the budget. Terms are maximal alphanumeric runs, so the `0x00` separator is unambiguous and a term's posting list stays one contiguous range: exact-term lookup, the FTS-031 prefix union and FTS-032 phrase anchors are all key-range scans. `total_len`/`total_docs` stay resident as counters, kept in step with the keyspace on re-index and delete. BM25 scores are unchanged (same inputs, same formula); the FTS-022 rebuild lifecycle is unchanged, and `verify_index_integrity` compares contents instead of the dropped `PartialEq`. Recovery now seeds full-text indexes with `fresh_like` rather than cloning the empty store's handles — the same rule the paged B-tree/unique indexes already followed.
